# 🐍 PyCode Assistant

تطبيق ويب يشغّل نموذج Transformer صغير (مدرَّب من الصفر على CoNaLa) يحوّل
وصفًا بالإنجليزية إلى سطر كود بايثون، مع واجهة دردشة عصرية متجاوبة مع
الموبايل، وبثّ الكود توكن بتوكن أثناء التوليد الفعلي.

## 1. التشغيل محليًا (للتجربة على جهازك)

```bash
pip install -r requirements.txt
python app.py
```

افتح المتصفح على `http://127.0.0.1:5000` — أو من موبايلك عبر عنوان IP
جهازك على نفس شبكة الواي فاي (مثلاً `http://192.168.1.5:5000`).

## 2. رفع المشروع إلى GitHub (خطوة لازمة قبل النشر)

معظم خدمات الاستضافة المجانية (بما فيها الموصى بها أدناه) تنشر مباشرة من
مستودع GitHub:

```bash
git init
git add .
git commit -m "PyCode Assistant"
```

ثم أنشئ مستودعًا جديدًا فارغًا على GitHub وادفع الكود إليه (`git remote add
origin ...` ثم `git push`).

**تنبيه:** ملف النموذج (`conala_codegen_best.keras`, ~44 ميغابايت) وملف
التوكنايزر يجب أن يُرفعا مع باقي الملفات — لا تضعهما في `.gitignore`.

## 3. النشر على Render (الخيار الموصى به — مجاني، بدون بطاقة ائتمان)

بحثت عن أحدث خيارات الاستضافة المجانية المناسبة لتطبيقات Flask، و**Render**
هو الأنسب حاليًا لمشروعك: يدعم Flask تلقائيًا، لا يطلب بطاقة ائتمان، ويمنح
750 ساعة تشغيل مجانية شهريًا.

خطوات النشر:
1. أنشئ حسابًا على [render.com](https://render.com) وسجّل الدخول عبر GitHub.
2. اضغط **New → Web Service** واختر المستودع الذي رفعته.
3. الإعدادات:
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `gunicorn app:app --workers 1 --threads 4 --timeout 120 --bind 0.0.0.0:$PORT`
     (موجود مسبقًا في ملف `Procfile` المرفق، وRender يكتشفه تلقائيًا غالبًا)
   - **Instance Type:** Free
4. اضغط **Create Web Service** وانتظر اكتمال البناء (قد يستغرق 5-10 دقائق
   بسبب حجم تنسورفلو).
5. بعد الاكتمال ستحصل على رابط عام بصيغة
   `https://your-app-name.onrender.com` — هذا هو الرابط الذي ترسله لأصدقائك.

### ⚠️ نقطة مهمة جدًا: حدود الذاكرة على الخطة المجانية

الخطة المجانية في معظم خدمات الاستضافة (Render وغيرها) تمنح عادة **512
ميغابايت رام فقط**. تنسورفلو وحده (حتى نسخة `tensorflow-cpu`) يستهلك جزءًا
كبيرًا من هذا عند التحميل. نموذجك صغير جدًا (44 ميغابايت فقط)، لذا **الأرجح
أن يعمل**، لكن إن واجهت خطأ توقف مفاجئ للخادم (`Out of Memory` أو
`Application failed to respond`) بعد النشر، فهذا هو السبب المرجّح، والحل
عندها:
- الترقية لخطة مدفوعة برام أكبر (عادة رخيصة جدًا، $5-7/شهر)، أو
- تجربة خدمة أخرى بحدود رام أعلى في خطتها المجانية.

### ⚠️ نقطة أخرى: "النوم" بعد عدم الاستخدام (Cold Start)

الخطة المجانية توقف الخادم تلقائيًا بعد فترة من عدم الاستخدام، فأول طلب بعد
فترة توقف قد يستغرق 30-50 ثانية للاستجابة (إعادة تشغيل + تحميل النموذج من
جديد). أخبر أصدقاءك بهذا حتى لا يظنوا أن التطبيق معطوب إن تأخر أول رد.

## 4. بنية المشروع

```
app/
├── app.py                          # خادم Flask + منطق التوليد والبث
├── conala_codegen_best.keras       # أوزان النموذج
├── conala_bpe_tokenizer.json       # التوكنايزر
├── requirements.txt
├── Procfile                        # أمر تشغيل الإنتاج (gunicorn)
└── templates/
    └── index.html                  # واجهة الدردشة
```

## ملاحظة أخيرة

هذا نموذج **تعليمي** مدرَّب على بيانات قليلة نسبيًا، لذا الكود المولَّد قد
يكون غير صحيح نحويًا أحيانًا — هذا متوقع وليس عطلاً في التطبيق. الواجهة
تعرض شارة "نموذج تعليمي" توضيحية لهذا السبب.
